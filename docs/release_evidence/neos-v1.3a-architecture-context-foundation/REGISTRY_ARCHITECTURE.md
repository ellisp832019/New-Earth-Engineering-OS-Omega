# Registry Architecture

NEOS registry is a projection and governance layer on top of existing intelligence.

## Existing owners reused

- Project Genome remains the canonical project snapshot owner.
- Semantic Intelligence remains the canonical source for symbols, features, APIs, and configuration evidence.
- Portfolio / Ecosystem Intelligence remains the canonical source for cross-project relationships and portfolio context.
- Engineering Memory remains the canonical source for decision chronology and memory records.
- Requirements Intelligence remains the canonical source for requirements and verification evidence.
- Decision Intelligence remains the canonical source for decision recommendations and release readiness.
- Hardware Intelligence remains the canonical source for hardware evidence.
- Firmware Intelligence remains the canonical source for firmware evidence.

## Registry ownership

- contract envelope
- provenance reconciliation
- drift detection
- declared-vs-observed comparison
- registry health
- impact orchestration

## Registry non-ownership

- source-code parsing
- semantic extraction
- capability discovery from raw source
- dependency truth reconstruction
- requirements parsing
- decision scoring
- hardware parsing
- firmware parsing
- actuator authority
