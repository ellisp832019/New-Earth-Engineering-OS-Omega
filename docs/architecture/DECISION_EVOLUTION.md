# Decision Evolution

Decision evolution tracks how engineering choices move from proposal to acceptance, implementation, supersession or rejection.

## Statuses

- proposed
- accepted
- implemented
- superseded
- rejected
- deprecated

## What to track

- decision chronology
- affected features
- affected domains
- affected symbols
- affected APIs
- affected configuration
- related risks
- replacement decisions

## Evidence sources

- ADRs
- decision logs
- release notes
- milestone docs
- explicit follow-up records

## Failure mode

Do not assume a commit message is a decision. A commit is only one possible evidence source.
