# Operating Model

## Project lifecycle inside NEOS

1. Register project.
2. Establish source-of-truth manifest.
3. Scan repository.
4. Review derived findings.
5. Promote selected derived facts to canonical records if required.
6. Track changes.
7. Attach evidence.
8. Prepare release.
9. Archive release snapshot.
10. Continue evolution.

## Human authority
Humans own requirements, release decisions, safety decisions and canonical claims. Automation may recommend, detect and draft.

## Change control
Architecture-impacting changes should produce an ADR. Data model changes require a migration. New plugin capabilities require capability declarations and tests.
